Papyrus Lint catches bugs that CreationKit's compiler lets through

PapyrusCompiler.exe only checks that a script is syntactically valid — it will happily compile a script that dereferences a None object at runtime, passes a String where an Int is expected, returns the wrong type from a function, compares an Int to a Float inexactly, or contains a branch that can never execute. Papyrus Lint scans your .psc source for exactly these patterns before you ship, on top of the formatting/style issues a linter usually catches — as a desktop app, a CLI, and editor extensions.

What is a linter?

A linter is a tool that scans source code for patterns that are likely to be mistakes, bad practice, or inconsistent style, without actually running the code. It works from heuristics — recognizable patterns known to often cause problems — rather than proving that a given line is definitely wrong. Because of that, a linter can produce false positives. Treat every diagnostic as advice, not a guaranteed defect report: use your own judgment, and use an ; @disable comment to silence a rule you've decided doesn't apply.

What this is NOT

A compiler (it uses the standard Papyrus compiler under the hood), an editor, a guarantee a script is fit for purpose, or a replacement for proper testing.

What this IS

A desktop app, standalone CLI, and editor extensions that all share one lint/repair engine, so a diagnostic looks and behaves the same everywhere you run it.

Implemented lints

Every rule works from raw source or lexer tokens rather than requiring a script that parses cleanly. See the full README table for the complete, detailed description of every lint and its automatic fix.

Formatting

Lint Description Auto-fix
Trailing whitespace Flags lines that end with trailing spaces or tabs. ✓
Space after comma Requires whitespace after commas in argument lists. ✓
Semicolon at end of line Requires or forbids trailing semicolons, according to the configured setting. ✓
Formatting checks Flags lines whose indentation doesn't match the configured style/width. ✓
Whitespace interrupting chaining Flags a space or tab immediately before or after a . member/method access. ✓
Exclamation mark spacing Flags a ! negation operator not followed by exactly one space. ✓
Type name casing Flags a script's declared type name if it doesn't follow the configured convention. ✓
Identifier casing Flags a declared function/event, property, state, parameter, or variable whose name doesn't match the configured style. ✓
Operator spacing Requires exactly one space on either side of logical/comparison operators. ✓
Property sorting Flags a property not sorted by type/name or not declared right after ScriptName. Disabled by default. ✓

Performance

Lint Description Auto-fix
Forbidden/discouraged function usage Flags calls to functions that are usually unintentional performance bottlenecks.
Slow function usage Flags calls with a faster equivalent available; the fix applies the supplied replacement. ✓
Short wait/update interval Flags Wait/RegisterFor(Single)Update(GameTime) calls below a configured interval.
Repeated GetValue() calls Flags a global's value re-read across an If/ElseIf chain instead of cached once. Disabled by default.

Reliability

Lint Description Auto-fix
Getter usage without saving result Flags standalone calls to Get* functions whose returned value is discarded.
Strict boolean check Flags conditions that rely on Papyrus's implicit conversion to boolean.
Argument type check Flags call-site arguments whose type doesn't match the callee's declared parameter type.
Return type check Flags Return statements whose value's type doesn't match the declared return type.
Inherited function override Informs when a function shares a name with one declared on the Extends chain.
Argument naming consistency Flags a parameter name that doesn't match the parent script's same-named function.
State function signature mismatch Flags a state function/event whose parameters or return type don't match its empty-state declaration.
Strict numeric type check Flags implicit Int/Float comparisons without an explicit cast.
Explicit return on every path Flags a typed function/event with a path that falls off the end without a Return.
Unresolved script reference Flags a script reference that can't be resolved against the configured source directories.
Non-static function call Flags a Script.Function() call whose target isn't declared Global.
Static function called via instance Flags a Global function called through an object reference instead of by script name.
GoToState state reference Flags a GoToState(...) target that isn't declared on the script, likely a typo.
Total named state count Flags a script whose combined states (with its ancestry) exceed the engine's limit of 128.
Multiple Auto states Reports more than one Auto state in a script, or across its ancestry.
Conflicting script versions Flags same-named scripts with different contents in separate source directories.
FormID hex notation Flags a FormID literal compared against GetFormID()/GetFormFromFile not written in hex.
Property/variable named as script Flags a property or variable whose name matches the script it's declared in, a compile error.

Bugprone

Lint Description Auto-fix
Implicit Float-to-Int conversion Flags a Float value used where an Int is expected without an explicit cast.
Int/Int division widened to Float Flags Int / Int division into a Float slot, since Papyrus truncates it first.
Unreachable statement Flags statements that follow a Return within the same block.
Static condition Flags conditions that fold to a constant true/false regardless of runtime state.
Division by zero Flags a divisor that's a compile-time-constant zero.
Empty loop/conditional body Flags a seemingly useless While/If/Else body.
Invariant loop condition Flags a While whose condition depends on a variable never assigned in its body.
None used as an existing Form Flags a member/method access on a value still known to be None.
Local variable used before assignment Flags a read of an uninitialized local before anything assigns it a value.
Local variable shadowing Flags a local variable whose name matches a Property on the same or a parent script.
Parameter reassignment Flags a function/event parameter assigned a new value anywhere in its own body.
Form parameter used without a None check Flags a member/method access on a Form parameter not yet confirmed non-None. Disabled by default.
Unchecked cast Flags a member/method access on an as cast result before it's checked against None.

Other

Lint Description Auto-fix
Unused script properties Flags Property declarations never referenced elsewhere in the script.
Cyclomatic complexity Flags functions/events exceeding a configurable complexity threshold.
Unused or write-only local variables Flags a local variable whose value is never read back.
Prefer named arguments Flags a positional argument the configured setting prefers passed by name instead.
Useless downcast Flags an as cast to a type the value's already-known type extends or matches.
Unused disable directive Flags unknown @disable rule ids or directives that suppress no diagnostic. Disabled by default.
Magic numbers Flags a numeric literal used directly instead of through a named constant. Disabled by default.
Non-base-game native function usage Flags a Native function not part of the base game, a sign it needs SKSE/F4SE. Disabled by default.
GlobalVariable no-op write Flags a SetValue call that doesn't provably change the value. Disabled by default.

Add a trailing ; @disable <rule-id>[, <rule-id>...] comment to a line to suppress diagnostics from those rules on that line only (e.g. action = 1 ; @disable float-to-int); a bare ; @disable suppresses every rule on the line. See the README for the full list of rule ids.

Command-line interface

Besides its GUI, Papyrus Lint runs non-interactively via a standalone PapyrusLinterCLI binary (or the desktop app's own executable, launched with an .achlist/.psc path), supporting automatic fixes and structured JSON output. 

PapyrusLinterCLI path/to/project.achlist
PapyrusLinterCLI init
PapyrusLinterCLI path/to/Example.psc
PapyrusLinterCLI fix path/to/project.achlist
PapyrusLinterCLI fix --type trailing-whitespace path/to/Example.psc
PapyrusLinterCLI --tag style path/to/project.achlist
PapyrusLinterCLI --json path/to/project.achlist
PapyrusLinterCLI --config path/to/papyrus-lint.yaml path/to/Example.psc
PapyrusLinterCLI --script-root path/to/SharedScripts path/to/project.achlist
PapyrusLinterCLI --output path/to/report.json --json path/to/project.achlist

It exits 0 when nothing failing was found, 1 when something was, and 2 on a usage or I/O error — so it can gate a CI step on a clean lint run. The preferred way to run it in CI is the Papyrus Lint GitHub Action (idrinth/papyrus-lint-action), which posts findings as inline PR review comments. See the README for every flag.

Configuration

Lint/fix behavior is configured via an optional papyrus-lint.yaml (or .yml) file at the project root — next to the .achlist, or two directories above a bare .psc. Any key it omits falls back to its documented default. It controls formatting (semicolons, indentation, casing), which rules are enabled, complexity thresholds, CLI failure levels, and the compiler path — PapyrusLinterCLI init writes the full default file into a project with none yet.
